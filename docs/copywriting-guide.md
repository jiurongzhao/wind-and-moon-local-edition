# 文案规范 · 高级感与亲民化

> 本文件是「风月·本地版」全部用户可见文案的唯一基准。改任何界面文字、卡面文字、
> 报错、对外文档前先读这一页；与旧写法冲突时以本页为准。

## 0. 两条主轴

- **高级** = 具体（物证、磨损、可数的规则与数字）+ 克制（零感叹号、少形容词、不排比）+ 语域稳定。
  「高级」不靠辞藻，靠只有这个东西才有的细节。
- **亲民** = 零术语 + 结论先行 + 给下一步 + 第二人称「你」。
  「亲民」不靠卖萌，靠把工程语言翻译成人的处境。
- **一票否决**：面向玩家的界面与卡面里出现下列词即算缺陷——
  `token / GGUF / JNI / libllama / KV / ctx / engineMode / JSON / URI / 403 / 中位数 / 分片 / 原生桥 / 后端`。

## 0.1 柔和性分级（用户可见文案必须标级）

| 级别 | 适用场景 | 必须 | 禁止 |
|---|---|---|---|
| **高柔和** | 生成失败/被系统打断、第一次打开、聊天空态、倾诉类角色第一句、删除后的收尾 | 先接住当下处境，再给**且只给一个**下一步 | 道歉词、卖萌助词、空承诺 |
| **中柔和** | 常规状态、空态引导、记忆摘要、剧情/群聊开关、下载与保存成功 | 结论先行 + 下一步 | 寒暄、抒情、口号 |
| **低柔和（保持干脆）** | 破坏性操作确认、数据不可逆、安全/医疗/法务边界、精确数字与错误事实、引擎未就绪 | 一句事实、一句代价、一句动作；事实不得模糊 | 软化词（「其实/可能/要不」）；但**必须有退路句** |
| **零柔和（红线）** | 自伤/危机/情感依赖边界、许可证与版权、人身安全规则 | 只陈述事实与动作 | 玩笑、修饰、模棱两可、情绪绑架 |

- 角色台词可以是零柔和（探长/门卫/恐怖角色），**界面文案不得低于低柔和**：任何错误/拒绝都要给下一步。
- 组合规则：低柔和场景也允许「前挂接住句 + 后挂退路句」，但夹在中间的事实句必须干脆。
- **危机兜底**：倾诉/树洞类角色遇到自伤或危机信号，第一句固定「你现在的安全最要紧」，随后放慢、陪着，建议联系身边可信任的人与专业机构（不虚构号码与机构名）；该句单点维护在 docs，各卡引用同一句。

## 0.2 舒适性（读起来不费力）

- **短、可扫读**：用户可见的一句话不超过约 30 字；一项说明一行说完；设置项说明 ≤ 1 行。
- **一段一件事**：同一句里只给一个下一步动作，禁止一次抛三个选项。
- **零认知负担**：术语按第 1 节翻译；中英不并排；同一概念全站同一说法；按钮名与提示里的名字一致。
- **不制造焦虑**：不以「失败/错误」当主语；先给结果，再给原因；不说「数据丢失」「出问题」这类吓人的词，改用具体事实。
- **可预期**：同类操作的提示用同一句式；状态词固定；破坏性操作先讲清代价。
- **排版**：中文用全角标点，中英文/数字之间留一个半角空格；不叠括号；不堆 emoji 与符号；保留留白。
- **不啰嗦**：同一个意思只出现一次；已经写清的就别再补一句解释。

## 2. 报错模板

一律写「**发生了什么 + 我现在能做什么**」，不允许出现：

- Java/Python 异常对象、堆栈、`e.getMessage()`、`e.getClass().getSimpleName()`
- 内部方法名、桥方法名、代码变量（`engineStart`、`chat`、`engineMode`、`appInfo().filesDir`）
- 原始 URL、原始文件名、`packs` 数组名、`JSON` 解析细节

示例：
- ✗ `engineStart 参数错误: null`　→　✓ **启动信息不完整，请回设置页重新选一次模型**
- ✗ `无法打开文件选择器: SecurityException`　→　✓ **打不开文件选择，请确认已授予存储权限后重试**
- ✗ `代理失败: ConnectException`　→　✓ **连不上这个服务，检查一下地址和网络**

## 3. 状态与空态

- 状态：动词 + 结果，不喊口号、不加感叹号。保留 `启动 / 加载 / 就绪 / 未启动` 这几个既有状态词（测试断言依赖）。
- 空态：说清「现在缺什么 + 点哪个按钮」。按钮名必须与界面上的真实按钮一致。
- 同一动作全站一个说法：统一「还在生成中，点停止后再发」「先在『角色』页选一个」。

## 4. 卡面字段规范（cards/pack-*.json 与生成器）

- **人称**：面向玩家一律「你」；禁止「用户 / 玩家 / 起点是 / 世界观：/ 冲突：」这类策划字段腔。
- **name**：常用姓 + 可信名，禁止动词/器物当名（如「单人守」「阿羹」），跨包同名可控。
- **tagline**：一句话，**不加句尾句号**（全库统一）。
- **description**：把角色姓名嵌进去；「口头禅」加「」；同类信息（口头禅/缺点/最在意）最多用两种句式，避免全套填空。
- **personality**：名词短语为主，不原样复读 tagline。
- **first_mes**：形态要多样，不要 100% 以「（动作神态）」开头；可先出声、先给物件/声音，再带出人物。
- **system_prompt**：`/no_think` 是**功能指令，保留在数据里**（默认允许思考时它会关掉思考）；但它面向用户的说明文字统一叫「直接回答标记」，不写斜杠命令。
- 品牌名统一「风月·本地版」。

## 5. 不可破坏项（改文案时同时遵守）

1. **功能字符串**：引擎模式取值 `jni` / `server`、事件名、桥方法名、字段 key、`/no_think` 标记本身，不改。
2. **测试断言**：`tests/ui.test.mjs` 断言状态文案含 `启动/加载/就绪/未启动`、选项 value 为 `jni`、以及大量函数行为；改完必须跑通。
3. **校验器**：
   - `tools/check-creator.py`：taxonomy 必须 16 类，note 必须含「第三方卡片正文」，suggestedTags 必须包含自身。
   - `tools/check-banks.py`：字段条数下限、`CLAUSE_FIELDS` 需成句、`NO_PERIOD` 字段不能以句号结尾、版权黑名单。
   - `tools/build-pack-index.py`：`cards/index.json` 与 `app/assets/ui/packs/` 是**生成物**，不要手改 index.json；改脚本里的 note / META 再重新生成。
4. **品牌与数字**：README 与 docs 里的测试项数、线程默认值等以代码/实测为准，不允许互相矛盾。
